## Codebase Patterns

### Migration System
- **ClickHouse migrations**: Create `.sql` files in `etc/clickhouse/` using pattern `NNNN-description.sql`. Always use `CREATE TABLE IF NOT EXISTS` for idempotency (no version tracking).
- **PostgreSQL migrations**: Create C# classes in `src/Data/Migrations/` using pattern `NNNN_Description.cs` with `[Migration(NNNN)]` attribute. Use FluentMigrator API.
- **Extension methods**: Use `WithNanoIdColumn()` for IDs and `WithTimestamps()` for audit columns in PostgreSQL migrations.
- **TTL pattern**: ClickHouse tables use explicit `ttl` DateTime column with `TTL ttl` clause for automatic data expiration.
- **Partitioning**: ClickHouse analytics tables should partition by `toYYYYMM(timestamp)` for monthly partitioning.
- **Build verification**: Always run `dotnet build` after creating migrations to verify compilation.

### Ingestion Pattern
- **Fire-and-forget**: Accept request → buffer in-memory → return 202 Accepted → flush later via background worker
- **Controller pattern**: Validate payload → lookup app via IIngestionCache → check if locked → buffer → return success
- **App lookup**: Use `IIngestionCache.FindByAppKey(appKey, cancellationToken)` which returns `CachedApplication` with `Id` and `IsLocked`
- **Invalid app check**: Use `string.IsNullOrEmpty(app.Id)` (not null check)
- **Locked account**: Return `BadRequest("Owner account is locked")` (not 423 status)
- **Rate limiting**: Apply via `[EnableRateLimiting("PolicyName")]` attribute on controller actions
- **CORS**: Use `[EnableCors("AllowAny")]` and provide OPTIONS endpoint for preflight requests
- **Buffer structs**: Use readonly struct with `ref` parameters to avoid copying overhead
